# e2e/shards.txt — which e2e test runs in which CI job (#140).
#
# The `e2e` job reached 20.5-22.7 min against the rule docs/BUILD_LOG.md committed when it
# last died on its own deadline: "the suite wants SPLITTING, not a longer rope, if it passes
# 25 min". This file is the split. Three jobs run in parallel, each with its own -run.
#
# WHY AN EXPLICIT LIST AND NOT A PATTERN. `go test -run` matches names, and a pattern that
# matches nothing fails SILENTLY: no error, no skip line, just a test that quietly stopped
# being gated. An explicit list makes that impossible to do by accident, because
# TestEveryE2ETestIsInExactlyOneShard derives the full set of `func Test...` from the e2e
# sources by AST and refuses any test that is missing from here or listed twice.
#
# So adding an e2e test means adding a line here. That friction is the point: it is the same
# bargain as docs/mode-matrix.json, where a new mode cannot be added without someone
# recording what it does.
#
# ⚠️ The ORIGINAL proposal on #140 was to reuse the existing `ECOSYSTEM=npm|pypi|oci|maven`
# selectors. Do not. Each of those selects exactly ONE test (`-run TestNpmEndToEnd`), so four
# jobs built on them would have run 4 of the 89 tests and gone green faster than the job they
# replaced.
#
# FORMAT: <shard> <TestName> <seconds>
#
# The third column is the duration MEASURED in job 16576955361 (pipeline 2859816713), used to
# balance the shards by longest-processing-time-first. It is documentation of how the balance
# was chosen, not an assertion — nothing fails when a test gets slower. Rebalance with
# `sh scripts/e2e_shards.sh --rebalance <trace-file>` when the spread gets wide.
#
# TestRealDockerPullOfAnAllowedImageSucceeds carries an ESTIMATE (60s): it skipped in that run
# (the image ships no attestation manifests today), so it has never been measured here. The
# estimate is deliberately generous -- it does a real docker pull when it does run.
#
# Balance as committed: shard 1 = 6.9 min, shard 2 = 6.9 min, shard 3 = 6.9 min.
